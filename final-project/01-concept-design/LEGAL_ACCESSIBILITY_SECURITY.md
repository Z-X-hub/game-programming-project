# Legal, Accessibility, Security, and Ethics

This document records the Stage 1 planning notes for issues beyond the game mechanics. It supports the module requirement to consider legal, ethical, social, accessibility, and security issues where relevant.

## Legal And Licensing

Fox Dash uses existing resources as part of a student project, so the repository must clearly credit external work.

Planned credits:

- RedRunner-derived code and assets used as the starting reference/base for the runner project
- Kenney Platformer Characters used for character visuals
- Unity engine and any Unity package assets used by the project

Final submission notes:

- Keep licence and credit notes in the repository.
- Do not claim external assets as original work.
- Do not upload paid or restricted assets unless the licence allows it.
- Include third-party notices before the final submission if additional assets are added.

## Accessibility

Fox Dash is a small platform runner, but it can still be designed to be more accessible.

Current accessibility considerations:

- simple keyboard controls
- clear character roles on the menu
- large visual buttons on the main screen
- bright, readable art style
- automatic revive for the SOLDIER character as a more forgiving option
- quick restart flow after failure

Potential future improvements:

- key rebinding
- colour-blind friendly UI checks
- adjustable volume controls
- clearer on-screen control hints
- difficulty tuning for platform gaps and hazards

## Ethical And Social Considerations

Fox Dash is a cartoon runner with light platform hazards. It does not require realistic violence, gambling mechanics, chat, personal data, or online social features.

Design choices:

- keep hazards stylised and non-graphic
- avoid manipulative monetisation or gambling-style reward systems
- keep the game playable offline
- use character design in a respectful and non-stereotyped way

## Security And Privacy

The planned game is offline and does not need accounts, passwords, analytics, online chat, or personal data collection.

Security planning:

- no networked login system
- no collection of personal information
- no external server dependency for normal play
- use local settings only if needed
- avoid committing personal computer paths, secrets, or Unity cache folders to GitHub

## Professional Practice

The project should show steady GitHub progress. Documents, code, testing notes, and final presentation material should be committed in the correct stages so the development process is visible.
