# Fox Dash Project Structure

Fox Dash is a side-scrolling runner game. The main gameplay is concentrated in
one playable scene, while platform sections and background blocks are generated
continuously at runtime.

## Main Directories

- `Assets/Scenes`
  - `Play.unity`: the main game scene. It contains the camera, UI, player,
    audio objects, and terrain-generation entry points.

- `Assets/Scripts/FoxDash`
  - `GameManager.cs`: high-level game flow, start/pause/end state, respawn,
    score, coins, and save handling.
  - `Characters`: base character logic, character selection state, fast-run
    role, one-revive role, and double-jump role logic.
  - `TerrainGeneration`: terrain blocks, background blocks, and runtime
    generation rules.
  - `Collectables`: coin, chest, and collectable behaviour.
  - `Enemies`: hazard and enemy behaviour.
  - `UI`: start, pause, end, score, coin, menu guide, and death-feedback UI.
  - `Utilities`: camera, ground check, path following, and shared helpers.

- `Assets/Prefabs`
  - Reusable player, platform block, background block, enemy, coin, particle,
    and audio prefabs.

- `Assets/Sprites/FoxDash`
  - In-game character, UI, background, terrain, coin, and enemy sprites.

- `Assets/Sounds`
  - Character-action, collectable, enemy, environment, and UI sound effects.

- `Assets/SaveGameFree`
  - Local save-system reference used for coins, best score, and audio state.

- `Packages`
  - Unity package dependency configuration.

- `ProjectSettings`
  - Unity project settings. The game display name is maintained through
    `Assets/Editor/FoxDashProjectBranding.cs`.

- `THIRD_PARTY_NOTICES.md`
  - RedRunner, asset, save-system, font, and licence notices.

- `AI_DECLARATION.md`
  - Selective AI-use declaration for difficult implementation and debugging
    areas. It does not claim that the whole project was generated by AI.

## Runtime Flow

1. `GameManager` initialises UI, loads saved values, and listens to the player
   death state after `Play.unity` opens.
2. When the player presses Play, `GameManager.StartGame()` resumes game time.
3. On the start screen, the player can press `1`, `2`, or `3` to select
   `PLAYER`, `SOLDIER`, or `ADVENTURER`, then press the Play button.
4. `FoxDashCharacter` reads input every frame and controls horizontal movement,
   jumping, rolling, death feedback, and role behaviour. `PLAYER` is faster,
   `SOLDIER` can automatically revive once after falling or landing in water,
   and `ADVENTURER` can double jump before landing.
5. `TerrainGenerator` continuously creates terrain and background blocks ahead
   of the character and removes blocks that are far behind the run.
6. When the character dies, `GameManager` records the run score, updates best
   score, and opens the end screen.
7. The end screen shows death reason, run score, best score, new-record state,
   run coins, and total coins. The pause screen provides resume, restart, and
   home actions.

## Cleanup Rules

The repository should keep maintainable source files only. Unity-generated IDE
files, temporary caches, and local logs are not source evidence. `Library`,
`Temp`, `Logs`, and `UserSettings` can be rebuilt by Unity and should not be
committed.
