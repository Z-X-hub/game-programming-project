# Fox Dash Development Plan

This plan follows the module assessment structure. The project will not be uploaded as one final dump. Each stage will be committed as evidence of planning, development, testing, reflection, and presentation preparation.

## Assessment Breakdown

- Game Concept and Design: 20%
- Final Game: 60%
  - Game and Report: 40%
  - Game Demo / Presentation: 20%
- Professionalism: 20%

## Stage 1 - Game Concept and Design (Complete)

Goal: define the final game idea, the intended player experience, the realistic scope, design reasoning, tools, assets, and relevant legal, ethical, accessibility, and security considerations.

Evidence:

- `01-concept-design/GAME_CONCEPT.md`
- `01-concept-design/CHARACTER_DESIGN.md`
- `01-concept-design/SCOPE_TOOLS_ASSETS.md`
- `01-concept-design/LEGAL_ACCESSIBILITY_SECURITY.md`

Status: complete.

## Stage 2 - Core Playable Game (Complete As Development Evidence)

Goal: organise the Unity project source evidence and record visible progress on a playable Fox Dash vertical slice.

Evidence:

- `02-game-development/README.md`
- `02-game-development/SOURCE_MANIFEST.md`
- `02-game-development/RUN_INSTRUCTIONS.md`
- `02-game-development/IMPLEMENTATION_NOTES.md`
- `02-game-development/UPLOAD_NOTES.md`

Implemented and documented:

- Unity project source structure
- Main playable scene
- Character selection screen
- Three character abilities
- Platform generation and obstacle flow
- Score, coins, UI feedback, audio, and animation notes
- Build/run instructions
- Unity generated-folder exclusions

Status: complete as Stage 2 development evidence.

## Stage 3 - Testing and Iteration (Next)

Goal: prove that the game was tested, debugged, and improved over time.

Planned evidence:

- Playtesting notes
- Bug list and fixes
- Before/after improvement notes
- Stability checklist
- Known limitations

Status: next stage.

## Stage 4 - Report

Goal: write the final report after enough game and testing evidence exists.

Planned evidence:

- Design choice explanation
- Technical decision explanation
- Problems and limitations
- Testing evidence and changes made
- Reflection on how the game changed from concept to final version

Status: not started.

## Stage 5 - Demo / Presentation

Goal: prepare a clear demonstration of the final playable vertical slice.

Planned evidence:

- Demo order
- Feature explanation notes
- Programming explanation notes
- Reflection and question preparation

Status: not started.

## Professional GitHub Practice

- Commit work in meaningful stages.
- Keep the Kanban updated whenever stage status changes.
- Keep documentation close to the evidence it describes.
- Do not commit Unity generated cache folders such as `Library`, `Temp`, `Logs`, or `UserSettings`.
- Use the repository to show steady development, not only the final result.
